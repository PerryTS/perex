# Implementation milestones

Each milestone records what is implemented and what is still open. Progress on one does not establish another: conformance is not performance, and engine microbenchmarks are not host measurements.

1. **Exact input and result model — implemented.** Lossless code-unit/code-point cursors, reverse traversal, half-pair positions, no-copy span access and scoped-borrow relocation tests. No converted subject buffer is permitted for production traversal.
2. **Compiler and program format — implemented.** A bounded arena parser and iterative emitter write a validated relocatable u32 program; capture operands support more than 254 groups. Unicode 17.0.0 case equivalence and character properties come from pinned, licensed UCD inputs, and property references share immutable tables instead of copying intervals into each program. Named captures and duplicate alternatives use an optional packed table in the same program. Open: the `v` flag's properties of strings, and format-size optimization.
3. **One evaluator — implemented.** The ordered VM implements captures/reset, counted and nullable repeats, assertions/backreferences, explicit limits and caller-owned scratch. Suspension and explicit scratch replacement preserve partial work and release resource views between advances, and owner-bound reborrowing costs constant work. Extend the same evaluator with deterministic complete-answer witnesses; never silently fall back to another engine.
4. **Perry adapter — implemented, in Perry.** A traced program reference, safe input borrows, collecting/reentrant operations, result materialization and the JS operation paths, plus an owned-buffer adapter for Perry's build tooling. This implementation belongs in Perry, not this crate.
5. **Conformance and reliability — measured, fuzzing open.** Test262 pattern conformance ([conformance](conformance.md)), differential harnesses against Node including paused, relocated and regrown execution, resource-limit tests and Perry's GC/lifetime witnesses. Open: structured differential fuzzing. Reference fixture checks alone do not satisfy this milestone.
6. **Performance and adoption — adopted, host measurements open.** Perex is Perry's only regular-expression engine. Engine CPU figures against V8 are in [performance](performance.md). Open: choosing between the interpreter and the [compilation tier](compilation.md), and controlled whole-application CPU/RSS comparisons in the host. Perry's build-tooling patterns also run slower than they did on the `regex` crate. Meet the per-case CPU and RSS requirements in `performance.md`; aggregate wins cannot conceal losing cases.
7. **Reusable release and compilation tier — released, tier partial.** Published on crates.io as `perex`. The compilation tier emits AArch64 code for a documented subset, bounded by a work budget and checked by a verifier before it is returned; x86-64 and the path-selection rule remain, per [compilation](compilation.md).
